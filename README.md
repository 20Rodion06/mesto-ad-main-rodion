# Атлас — места и истории (Mesto + Supabase)

Учебное приложение для коллекции фотографий и мест. Использует **HTML, CSS, JavaScript, Vite** и **настоящий Supabase Auth + REST API**. Структура исходного проекта сохранена: 81 файл, 62 папки, методология БЭМ и отдельные JS-модули.

## Возможности

- Анонимная авторизация через Supabase Auth без ввода почты и пароля.
- Загрузка профиля и карточек из таблиц `profiles`, `cards`, `likes` в Supabase PostgreSQL.
- Редактирование имени, описания и URL аватара через HTTP `PATCH`.
- Добавление карточки через `POST`, удаление собственной карточки через `DELETE`.
- Лайки и снятие лайков через `POST` / `DELETE` таблицы `likes`.
- Информация о карточке и её авторе, поиск, фильтры, валидация форм, модальные окна.
- Отдельная автономная демоверсия с 6 иллюстрациями и `localStorage` по адресу `/?demo=1`.

**Обычный адрес сайта** (например, `http://localhost:5173/`) работает с Supabase. **Только** `?demo=1` включает локальный режим. При ошибке сервера приложение показывает сообщение, а не выдаёт демоверсию за работу с API.

## Запуск на Windows

1. Распаковать архив. Открыть **внутреннюю папку** `mesto-ad-main-rodion` с файлом `package.json` в Visual Studio Code.
2. Открыть терминал в этой папке, выполнить:

   ```powershell
   npm.cmd install
   npm.cmd run dev
   ```

3. Открыть URL, выданный Vite (обычно `http://localhost:5173/`).
4. Для работы без сервера открыть `http://localhost:5173/?demo=1`.
5. Остановить сервер: `Ctrl+C` в терминале.

Для продакшен-сборки: `npm.cmd run build`; Vite создаёт папку `dist`. Её можно разместить на Netlify Drop или другой статической платформе. Для проверки собранной версии: `npm.cmd run preview`.

## Подключение к Supabase

В `src/scripts/components/api.js` уже настроены:

- Проект Supabase `rodion-mesto` (базовый URL `https://jjffshsfepjdpljqamfd.supabase.co`).
- **Publishable key** (публичный ключ, предназначенный для браузерных приложений).
- Встроенные HTTP-запросы через `fetch` — сторонний SDK не требуется, дополнительные пакеты для API не нужны.

**Никогда не добавляйте** в исходники пароль базы, ключи `sb_secret_...`, `service_role` или чужой учебный API-токен.

Схема базы данных была создана отдельно в Supabase SQL Editor:

| Таблица | Используемые столбцы |
|---|---|
| `profiles` | `id`, `name`, `about`, `avatar` |
| `cards` | `id`, `name`, `link`, `owner_id`, `created_at` |
| `likes` | `card_id`, `user_id` |

При создании анонимного пользователя триггер `on_atlas_user_created` должен создавать соответствующую строку в `profiles`. В **Authentication → Sign In / Providers** разрешены **Anonymous Sign-Ins**. Роли и политики RLS разрешают чтение аутентифицированным пользователям, изменение профиля — владельцу, удаление карточек — их авторам, лайки — авторизованному пользователю от своего имени.

### Как проверить, что работает именно API

1. Откройте сайт **без** `?demo=1`.
2. На чистой базе список сначала пустой — это **нормально**. Создайте карточку через кнопку «Добавить место».
3. Перезагрузите страницу: карточка должна остаться.
4. Откройте DevTools (`F12`) → **Network**: запросы к `.../auth/v1` и `.../rest/v1` подтверждают работу Supabase.
5. В Supabase → **Table Editor → cards** убедитесь, что карточка действительно появилась в таблице. Проверьте добавление/удаление лайка и изменение профиля.
6. В другом браузере создаётся **другая** анонимная учётная запись; чужие карточки видны в общей коллекции, но удалять их нельзя.

Анонимная сессия хранится в localStorage браузера, а не пароль базы. Очищение данных сайта или другой браузер приведёт к **новому анонимному пользователю**: без привязанного логина старые собственные карточки будет нельзя редактировать/удалять.

### Безопасность и публикация

- Publishable key **не является секретом**. Доступ к данным ограничивается **RLS**, а не сокрытием ключа. Не отключайте RLS.
- Анонимный вход открыт для всех посетителей сайта. Для публичной публикации Supabase рекомендует включить CAPTCHA/защиту от автоматических регистраций (при включении CAPTCHA потребуется передавать токен проверки в запрос анонимного входа; текущее приложение этого не реализует). Без такой настройки лучше не распространять публичную ссылку широко.
- Если в старом публичном репозитории был чужой токен, его простое удаление из файла не очищает **историю Git**. Владельцу токена нужно его отозвать, историю — очистить с учётом возможных внешних копий.
- Подключение к собственному Supabase **технически заменяет** учебный API, но соответствие неизвестным требованиям исходного задания проверяется отдельно.

## Организация проекта

- `index.html` — разметка страницы, окон и шаблонов.
- `src/pages/index.css` — вход в стили.
- `src/blocks/` — CSS-компоненты по БЭМ.
- `src/scripts/index.js` — состояние интерфейса и обработчики событий.
- `src/scripts/components/api.js` — Supabase Auth, REST API, явная автономная демоверсия.
- `src/scripts/components/card.js` — отображение карточки, лайков и кнопок.
- `src/scripts/components/modal.js` — модальные окна.
- `src/scripts/components/validation.js` — проверки форм.
- `src/images/`, `src/vendor/` — изображения, шрифты и normalize.css.
